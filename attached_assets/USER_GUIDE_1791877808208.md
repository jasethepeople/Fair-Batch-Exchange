# Fair Exchange: User Guide

Fair Exchange is a **simulation** of a batch-auction exchange. It does not touch real money, wallets, or a blockchain. Everything resets when the API server restarts.

## Run it

Commands from `replit.md`:

```
pnpm install
pnpm --filter @workspace/api-server run dev        # API (port 5000)
pnpm --filter @workspace/fair-exchange run dev     # web app
```

`replit.md` lists `DATABASE_URL` as a required env var. The simulation itself keeps its state in memory.

## Use it

1. **Place a sealed order.** Pick buy or sell, enter a quantity and a limit price (the worst price you'll accept), and submit.
2. **Watch the Sealed order queue.** Your order appears with a commitment code. Its terms stay hidden from the public view until the batch is revealed.
3. **Cancel if you change your mind.** You can cancel your own sealed orders until the batch is cleared.
4. **Clear the batch** from the result card. The button is enabled once the committee has enough shares (3 of 5) and at least one order exists.
5. **Read the result.** Everyone in the batch trades at the same clearing price. Order terms are revealed after clearing.

## Reading results

- **Clearing price:** one price for every fill in the batch.
- **Matched volume:** total quantity that traded.
- **Order status:** FILLED, PARTIALLY_FILLED, UNFILLED, CANCELLED, or ABORTED.
- **Partial fills:** orders at the edge price level share the remaining quantity pro rata.
- **Committee shares:** shows how many simulated validators released their share. Below the threshold, the batch cannot be revealed.
- **Audit log:** a running record of what happened.

## Failure lab

Try **Quorum failure**, **Reveal timeout**, or **Invalid order** to see the batch abort with no trade and no terms revealed. **Reset simulation** opens a fresh batch.

## What is not real

Orders are not encrypted (the server holds plaintext), there are no wallet signatures or asset transfers, and the committee is simulated. Don't treat any indicator in the app as a security claim.
